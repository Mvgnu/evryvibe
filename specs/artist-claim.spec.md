# Artist profile claims

An artist can claim an existing DJ profile through an Instagram DM to @evryvibe. The artist follows the account and sends CLAIM. A verified Meta webhook identifies the sender; the server checks their Instagram username against the unique stored profile and asks Meta for `is_user_follow_business`. A matching, unclaimed DJ and a confirmed follow receive a short-lived single-use link in the same conversation. No claim code or user-submitted name establishes identity. Missing, ambiguous, already-owned or unverified identity, a missing follow, and API failure must not grant access. Follow status is checked at claim time.

Redeeming the link atomically creates a durable, revocable session scoped to the one DJ. Secrets are random, stored only as hashes, expire, and are never logged. Cookies are HttpOnly, SameSite and Secure on HTTPS; mutations validate origin and session. A claimed artist can edit their own profile biography and bounded HTTPS links and single-address mailto booking links. Public discovery stays accessible without signing in. Artist-managed values take precedence over collector updates and retain provenance. Artist claims must never allow editing other DJs.

Meta webhook subscriptions, verified public HTTPS, business-account permissions, app review and real account credentials are operational prerequisites; mock tests are not a live Meta integration. Artists can post events with venue address, time, lineup and external ticket URL, and upload an event cover. An independently configured, self-hosted Nominatim endpoint resolves addresses to candidate coordinates; the artist confirms the intended match and unknown locations are never silently guessed. The tile server does not provide geocoding. Artist-submitted event provenance and uploaded media require explicit storage and ownership; do not label functionality as available until implemented and verified.
